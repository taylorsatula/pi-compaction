# packages/compaction/ — Mira-style coding checkpoint compaction

Intercepts pi's `session_before_compact` event and replaces default compaction with an LLM-generated engineering handoff summary featuring model-selected cut points and full artifact tracking.

## Rules

- Bails early if `customInstructions` starts with `[planmode pre-implementation]` — plan-mode owns its own compaction.
- `request_compaction` gates on `handoff_url`: validated in `execute()` (stat: existing file; `file://` prefix normalized). Missing/empty/bad path → `isError: true` nudge naming the session-handoff skill and the retry shape. The param is schema-optional on purpose: the omitted case must reach `execute()` so the nudge (not the harness's generic validation error) is the reply.
- The handoff path travels to the compaction event as the first `customInstructions` line: `Session handoff document: <path>` (format/parse pair in `handoff-reference.ts`). The main handler parses it out, records it in `wrapSummary` RECOVERY and `details.handoffUrl`. A `/compact` with the same line gets identical treatment.
- `--mirastyle-compaction-autocontinue` (boolean, default off): when on, `ctx.compact({ onComplete })` sends a user message pointing at the handoff so the agent self-orients and resumes. `onComplete` is the only safe injection slot — `session_compact` fires before `_clearManualCompactionState()`, and `pi.sendUserMessage` → `prompt()` throws while compaction state is uncleared (agent-session.js ~1648, ~2305-2327). Both callbacks wrap their bodies in try/catch: at print-mode exit the runtime is torn down mid-compaction and any ctx/pi access throws the stale-runtime error.
- Substrate boundaries measured 2026-10-27: print mode resolves `prompt()` at settle and exits without waiting for an agent_end-queued compaction (the compaction is lost); boolean extension flags must come after the prompt or as `=true`, because the generic arg parser (cli/args.js ~248) consumes the next bare token as an unknown flag's value.
- Summarizer model selection: checks `--mirastyle-compaction-provider` + `--mirastyle-compaction-model` flags → falls back to active model → falls back to Pi default compaction if no auth.
- Cutpoint selection prefers model-recommended entry IDs; validates against presented valid cutpoints; caps retained tokens at `MAX_MODEL_SELECTED_RETAINED_TOKENS` (15,000); falls back structurally if invalid.
- Failures (summarizer errors, empty responses) fall back to Pi default compaction — never crash the session.
- File ops tracked via `artifact-snapshot.ts`: extracts `read`, `write`, `edit` tool calls from assistant messages across compacted range, retained range, and all ranges.
- Previous Pi-generated compactions (not extension-generated ones) have their file ops merged into the current scope via `mergePreviousCompactionFileOps()`.
- Git snapshots scoped to session-touched paths only using `:(top)` pathspecs — never repo-wide status/diff.

## Architecture

Five-stage pipeline:

1. **Preparation** — `preparePromptContext()` serializes session entries via `serializeEntriesWithIds()`, computes file lists via `computeFileOpsForCutpoint()`, takes git snapshot via `safeGitSnapshot()`, collects valid cutpoint IDs.
2. **Summarizer Selection** — `resolveModelAuth()` picks model/provider based on CLI flags or active model fallback.
3. **LLM Generation** — `completeWithSummarizer()` sends system prompt + user prompt. User prompt includes previous checkpoint, deterministic metadata, new history, split turn prefix, retained recent context, and cutpoint instructions.
4. **Cutpoint Resolution** — `parseCheckpointResponse()` extracts body + recommended entry ID. `selectCutpoint()` validates against presented cutpoints, applies token cap, falls back structurally.
5. **Projection** — `projectSelectedCutpoint()` derives retained entries/messages, file ops, reference chars from final cutpoint. Builds summary via `wrapSummary()` and details via `buildCompactionDetails()`.
